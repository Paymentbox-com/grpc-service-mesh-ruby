# Generated Code

The generator is `grpc-service-mesh-gen` from the specification repository:

```sh
go install github.com/Paymentbox-com/grpc-service-mesh-api/cmd/grpc-service-mesh-gen@v0.8.0
grpc-service-mesh-gen --definitions definitions --ruby_out=lib/ruby
```

The generator reads `mesh/options.proto` from its own module version and
puts that directory on every `protoc` run.

For each service it emits a `Targets` module, an `RPCService` subclass, and an
`RPCClient` subclass. It writes them to one `<dir>_grpcmesh.rb` per directory
that holds a service, beside the `*_pb.rb` files protoc writes, and writes one
`service_maps.rb` at the output root. After the service classes, each
`<dir>_grpcmesh.rb` includes `GrpcServiceMesh::Metadata` into every message
class that an rpc in the file takes or returns.

This is the reference output for the specification's `examples/shop/order.proto`
and `deployment.proto`, kept in `spec/support/testproto/`, which the specs use
in place of a generated project. A real directory substitutes its own module
name, segments, transport name, and deployment group. `shop/shop_grpcmesh.rb`
is:

```ruby
# frozen_string_literal: true

# Generated by grpc-service-mesh-gen. DO NOT EDIT.
# source: shop/order.proto
# transport: nats
# deployment group: shop

require "grpc_service_mesh"
require "google/protobuf/empty_pb"
require_relative "order_pb"

module Shop
  module OrderTargets
    PLACE = ServiceMesh::Target.new(
      segments: ["shop", "OrderService", "Place"],
      kind: :route,
      metadata: {"deployment_group" => "shop", "transport" => "nats"}
    )
    PLACED = ServiceMesh::Target.new(
      segments: ["shop", "OrderService", "Placed"],
      kind: :topic,
      metadata: {"deployment_group" => "shop", "transport" => "nats", "consumer_group" => "audit"}
    )
  end

  class OrderService < GrpcServiceMesh::RPCService
    rpc :place, target: OrderTargets::PLACE, input: Shop::Order, output: Shop::Order, kind: :route
    rpc :placed, target: OrderTargets::PLACED, input: Shop::Order, kind: :topic
  end

  class OrderClient < GrpcServiceMesh::RPCClient
    rpc :place, target: OrderTargets::PLACE, input: Shop::Order, output: Shop::Order, kind: :route
    rpc :placed, target: OrderTargets::PLACED, input: Shop::Order, kind: :topic
  end
end

::Google::Protobuf::Empty.include(GrpcServiceMesh::Metadata)
::Shop::Order.include(GrpcServiceMesh::Metadata)
```

The per-transport `ServiceMaps` are emitted into `service_maps.rb` at the
output root, one `ServiceMesh::ServiceMap` constant per transport named by
the transport string in SCREAMING_SNAKE_CASE, such as `ServiceMaps::NATS`:

```ruby
# frozen_string_literal: true

# Generated by grpc-service-mesh-gen. DO NOT EDIT.
# One ServiceMap per transport, holding every Target served over it.

require "service_mesh"
require_relative "shop/shop_grpcmesh"

module ServiceMaps
  NATS = ServiceMesh::ServiceMap.new(targets: [
    Shop::OrderTargets::PLACE,
    Shop::OrderTargets::PLACED
  ])
end
```

## DSL Reference

`RPCService` and `RPCClient` share one class-level declaration.

```ruby
rpc name, target:, input:, kind:, output: nil
```

| Argument | Value |
|---|---|
| `name` | The rpc name in snake_case, as a Symbol. It is the name of the handler method on a service subclass and of the class method on the client. |
| `target:` | The `ServiceMesh::Target` constant for the rpc. |
| `input:` | The input message class protoc generated. |
| `output:` | The output message class protoc generated. It is required for `:route` and not used for `:topic`. |
| `kind:` | `:route` or `:topic`, matching `target.kind`. |

A `kind:` that does not match the target's kind raises
`ServiceMesh::KindMismatch` when the file loads. `.rpcs` returns every declared
rpc by name, including those declared on superclasses, as `GrpcServiceMesh::Rpc`
values.

On an `RPCService` subclass, the declaration records the rpc. `#endpoints`
returns a `ServiceMesh::Endpoint` for each route rpc whose method is defined by
the instance's class, at or below the declaring class. `#subscribers` returns a
`ServiceMesh::Subscriber` for each such topic rpc.

Each endpoint's and subscriber's handler decodes the payload with
`input.decode`, sets the decoded message's `mesh_metadata` to the inbound
metadata, and calls the method with it. An endpoint's handler then encodes the
response with `to_proto`, and sends the response's `mesh_metadata`, without
keys that start with `Mesh-Option-`, as the reply's metadata.

On an `RPCClient` subclass, the declaration defines the class method
`name(request)`. The method splits the request's `mesh_metadata` into message
metadata and transport options. A route method calls the transport client's
`request(message, options)` and decodes the reply, setting the response's
`mesh_metadata` to the reply's metadata without `Mesh-Option-` keys. A topic
method calls `publish(message, options)` and returns `nil`.

The transport is named by `target.metadata["transport"]`. The method looks up
its client through `GrpcServiceMesh.transport_router.client` on every call.

Targets are plain `ServiceMesh::Target` values. Their segments come from the
proto package, the service name, and the method name. Their metadata holds
`deployment_group` and `transport`, plus `consumer_group` when the method
option sets one. Nothing reads proto options at runtime.
